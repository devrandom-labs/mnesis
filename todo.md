## Fjall atomicity assessment

The lockfile resolves **Fjall 3.1.8 and lsm-tree 3.1.8**. Upstream sources, not only adapter comments, were checked. Fjall documents cross-keyspace atomic writes and a separate explicit persistence operation; consistency and durable acknowledgment are different guarantees. See [Fjall 3.1.8](https://docs.rs/fjall/3.1.8/fjall/) and [transaction database persistence](https://docs.rs/fjall/3.1.8/fjall/struct.SingleWriterTxDatabase.html#method.persist).

| Operation | What the current code guarantees | Work needed |
| --- | --- | --- |
| Single-stream append | Key validation precedes one transaction for head checks, events, indexes and counters on the bounded worker; wake follows the selected persistence policy (default `SyncAll`) | Preserve these guarantees in subsequent changes |
| `atomic_append_many` | Distinct targets and run shapes validate before storage work; one transaction spans runs and counters; a pre-commit error drops staged writes | Preserve A15/A18 boundaries and rollback evidence |
| Aggregate snapshot cache | Schema, version and state are one value committed under the selected persistence policy; cache writes are unconditional | Cache availability must not determine replay correctness |
| Projection checkpoint | Projection owns the matching state/position pair; revision CAS, schema/order checks and replacement share one writer transaction; incompatible rebuilds retain the revision | No transaction spanning event append and checkpoint is promised |
| Aggregate memory after append/replay | Checked commit ranges are derived from the batch; application panics poison the root, preventing access or reuse of partial state | Recovery loads a new root from committed history |
| Per-stream scan | Worker-managed iterator owns a view; returned payloads have actual 16-byte alignment. A16 sessions share one view across listing and reads | Artifact completeness is separate; fix truncated CBOR handling under A22 |
| Repository save plus aggregate snapshot | Event append followed by an optional best-effort cache write; replay budgets count actual tail work and a maximum-version snapshot needs no successor | Keep cache semantics explicit; no combined event/cache transaction is promised |

Keep the single writer transaction around read-check-stage-commit. Replacing it with a write batch after an unlocked head read would introduce an OCC race. Do not add transactions merely around already-atomic single values; fix the missing semantic guarantees at the appropriate layer.

### A01 — P1: validate actual Fjall key/value limits before staging

- [x] **Fixed.** Invalid stream IDs now return typed `InvalidKey` errors before opening a writer transaction, in both normal and atomic append. Both index modes use the documented 1–65,517-byte limit; raw snapshot/projection keys use 1–65,535 bytes on writes and reads. Key codecs account for layout overhead, state encoding checks the 12-byte header before allocation, and the existing event-frame encoder checks total u32 bounds. Activated the two original repros and added atomic rollback/wake/counter and state-key boundary cases. Verified with `nix develop -c cargo test -p mnesis-fjall --all-features --locked --lib --test audit_repros` (98 unit + 4 active regression tests passed; unrelated A02/A03/A16 ignored), and `nix develop -c cargo clippy -p mnesis-fjall --all-features --all-targets --locked -- -D warnings`.

**Original evidence:** the empty-key append panicked inside lsm-tree; the oversized-key append accepted 65,517 bytes then panicked at 65,518 with the default `$all` index.

**Code:** [stream_id.rs](crates/store/src/stream_id.rs), [wire_key.rs](adapters/fjall/src/wire_key.rs) `encode_event_key`/`encode_global_key`, [plan.rs](adapters/fjall/src/plan.rs), [partition.rs](adapters/fjall/src/partition.rs) `set_version`/snapshot/projection writes.

**Fix:** introduce typed boundary validation shared by append and atomic append. The locked lsm-tree `src/key.rs::InternalKey::new` enforces `u16` key length: **65,535 total bytes**, despite the rounded 65,536 in upstream overview prose. Primary-event overhead is 10 bytes; global-event overhead is 18. With the index enabled, raw stream IDs must be nonempty and at most 65,517 bytes. Without it the primary layout permits 65,525; a uniform 65,517 policy is a simpler valid design, but document the chosen contract. Validate raw snapshot/projection IDs separately and checked encoded value lengths against engine limits; these do not have the same key layout. Reject before any staging, with non-retryable errors.

**Accept:** cases at 0, 1, each chosen maximum and maximum+1; both index modes, normal/atomic append and snapshot/projection writes. No panic; rejected batches leave every row, head, counter and wake unchanged. Cover read-bound construction too. Test length calculations without allocating multi-gigabyte values.

### A02 — P1: persist and validate index mode across reopen

- [x] **Fixed.** A `SyncAll` transaction persists a versioned layout/index-mode manifest. Reopens reject mode changes, malformed/future manifests and nonempty unmarked databases with typed errors; empty unmarked databases initialize normally. The retained repro checks both directions and reads the unchanged original mode after rejection. Manifest tests cover empty-store reopen, empty unmarked initialization, legacy-data rejection and malformed/future bytes without overwriting them. Migration is explicitly export with the original adapter and import into a new database; no fabricated original global order. Verified by adapter unit/regression tests, all 47 Fjall conformance tests and adapter all-target Clippy.

**Original evidence:** `reopening_with_index_cannot_silently_omit_history` wrote with `AllIndex::Disabled`, closed, opened with the default mode, and saw one stream event but zero `$all` events through a successful read.

**Code:** [builder.rs](adapters/fjall/src/builder.rs) `open`; [partition.rs](adapters/fjall/src/partition.rs) `with_all_index`; [store.rs](adapters/fjall/src/store.rs) append/read-all paths.

**Fix:** persist an adapter layout/index-completeness manifest and validate requested mode at open. Reject incompatible mode changes with a migration-required error. For existing unmarked databases, inspect and validate rather than silently marking an incomplete index complete. Primary events currently do not retain the original global sequence, so rebuilding original cross-stream order from those rows alone is **not** a correct migration. Define any explicit reindex/reset operation and invalidate old checkpoints if it creates a new ordering.

**Accept:** both directions, enabled→disabled→enabled, empty database, existing unmarked complete/incomplete data, and interrupted manifest initialization. Successful `$all` access must never silently omit committed history.

### A03 — P1: enforce payload alignment after disk reads

- [x] **Fixed.** Envelope construction checks the actual frame address and copies an unaligned frame once into an `AVec` owner with 16-byte alignment. Aligned frames retain their original buffer. Activated the original flushed-disk repro and added checked bytemuck/rkyv decoding for primary and `$all` reads in memtables, flushed SSTs and compacted reopened databases, with variable IDs/metadata/frame sizes and compression enabled/disabled. Ownership tests check pointer reuse, one-copy repair and cloned-buffer lifetime. Verified with `nix develop -c cargo test -p mnesis-fjall --all-features --locked --lib --test audit_repros` (102 unit + 7 active regressions passed, A16 ignored), all 47 conformance tests and adapter all-target Clippy.

**Original evidence:** `disk_payloads_preserve_promised_alignment` appended 100 events, closed, forced both event keyspaces into SSTs with the public Fjall flush operation, reopened, and observed payload alignment offset 11 instead of 0 for the first row on this machine.

**Code:** [scan.rs](adapters/fjall/src/scan.rs) `build_envelope`; adapter [lib.rs](adapters/fjall/src/lib.rs) alignment claims; [wire.rs](crates/store/src/wire.rs), [codec.rs](crates/store/src/codec.rs). Current in-memory wire alignment tests do not exercise Fjall SST storage.

**Fix:** aligned offsets within a wire frame do not imply an aligned base pointer for Fjall's returned `Slice`. Retain ownership for the full borrowed decode lifetime. This audit demonstrates a broken alignment guarantee, not undefined behavior in the checked codecs.

**Accept:** real bytemuck/rkyv decoding and pointer checks for primary and `$all` reads, memtables, flushed SSTs, reopened DBs, varied key/frame lengths, compression and compaction. Copying should happen at most once per misaligned frame.

### A04 — P1: make durable acknowledgment an explicit adapter policy

- [x] **Fixed.** Public `Durability::{SyncAll, SyncData, Buffered}` has a syncing safe default; all four write paths use one policy-configured transaction constructor. `FjallStore::flush().await` persists completed buffered writes on the blocking worker and returns errors. The six-case policy regression covers both index modes, all write paths, flush, reopen and counter allocation. The [recovery test](adapters/fjall/tests/crash_recovery.rs) covers eight acknowledged-write/termination combinations. The [journal fault test](adapters/fjall/tests/journal_faults.rs) covers 18 real EIO combinations across journal writes, sync, normal/atomic append, snapshots, projections and explicit flush, using both syncing policies. Pre-staging rejection remains covered by A01 and conformance tests. Error cases publish no new live rows and emit no success wake; reopened histories, indexes, counters and state/position records must be complete, with exact payload comparisons and subsequent append checks. A sync error may recover the entire unacknowledged transaction, never a partial one. Parents require SIGKILL, an exact handshake and a timeout with cleanup; child test panics cannot count as process-crash success.

**Validation:** `nix develop -c cargo test -p mnesis-fjall --all-features --locked --test journal_faults --test crash_recovery --test audit_repros` passed (10 active tests, unrelated A16 ignored), as did adapter all-target Clippy with `-D warnings`. The C injector compiles with `-Wall -Wextra -Werror`; Nix sources retain it. Executed on Apple Silicon macOS; the Linux injector is retained for Linux CI, not claimed as executed here. Darwin tests cover both `F_FULLFSYNC` and `fsync`; Linux targets `write`, `fsync` and `fdatasync`. These are injected syscall errors and process termination, **not** power-loss/page-cache-loss experiments. Filesystem/device sync behavior remains an explicitly documented boundary.

**Original source evidence:** default Fjall transactions used `PersistMode::Buffer`, and the adapter exposed neither acknowledgment durability configuration nor explicit persistence despite calling successful events durable.

**Evidence:** locked Fjall `src/tx/single_writer/mod.rs::write_tx` sets `durability(Some(PersistMode::Buffer))` unless manual persistence is configured; `write_tx.rs::durability` permits a stronger mode. [DatabaseBuilder documentation](https://docs.rs/fjall/3.1.8/fjall/struct.DatabaseBuilder.html#method.manual_journal_persist) distinguishes OS-buffer flushing from persistence. Follow this path from [builder.rs](adapters/fjall/src/builder.rs) and both append implementations in [store.rs](adapters/fjall/src/store.rs).

**Fix:** add a named durability policy with an explicitly syncing safe default. Apply `SyncData`/`SyncAll`, as appropriate to the documented guarantee, to the transaction before commit. Apply the policy consistently to normal/atomic writes and projection checkpoints; expose an explicit fallible flush for buffered operation. Document what a sync error means, including uncertain commit outcomes and reload/idempotency requirements. Wake and successful acknowledgment must follow the promised persistence step. Do not equate graceful drop/reopen with power-loss durability.

**Accept:** test policy wiring for every write path; inject failures before staging, during commit and persistence; add the child-process recovery tests in A18. Prove consistency separately from acknowledged-write survival. Record hardware/filesystem limitations of any stronger fault-injection test.

### A05 — P2: isolate synchronous Fjall work from async executor threads

- [x] **Fixed.** A bounded, runtime-neutral worker handles event/state writes, flush, batched scans and cursor destruction. Inputs are owned after admission; frames are encoded before the writer lock. `BlockingConfig` independently bounds waiting jobs, live cursor/cleanup slots, rows and serialized bytes per batch. Full cursor admission returns typed `ScanCapacity`; each cursor holds a cleanup reservation, so dropping idle, queued, admission-waiting or running scans never waits for queue space or performs engine cleanup on the caller. Fourteen new deterministic tests cover saturation, cancellation before/after commit, single-thread executor progress, panic recovery, ordered batches, error/overflow fusion, worker-side destruction, explicit/canceled close and cursor-capacity rejection without blocking writes. Startup/recovery stays explicitly synchronous; `flush` and `close` are async. Reopen tests and the benchmark await close. Limits bound admitted work and serialized batches, not caller inputs or engine cache/backing allocations. Verified with `nix develop -c cargo test -p mnesis-fjall --all-features --locked` (207 passed, 0 failed, 2 ignored), the two additional cancellation regressions in the 10-test blocking-worker suite, adapter all-target Clippy and non-Postgres all-feature/all-target workspace compilation. Native journal faults and process-termination recovery pass with the worker.

**Original finding:** [store.rs](adapters/fjall/src/store.rs) implements async methods by taking synchronous engine locks and performing synchronous I/O; [scan.rs](adapters/fjall/src/scan.rs) and `StreamIdCursor::poll_next` advance disk iterators directly while polling. `async` does not offload that work. No latency number or observed starvation is asserted.

**Fix:** provide a bounded blocking-execution seam for writes, snapshot/projection access and scan batches, keeping the core API runtime-neutral or clearly isolating a runtime-specific adapter. Bound queued work and cursor memory; avoid spawning a task per row. Prepare pure encoding outside the writer lock where it does not weaken validation. Specify cancellation after commit: a dropped future must not imply rollback or suppress required wake/ack bookkeeping.

**Accept:** use an injected blocking barrier and single-worker executor to deterministically show an unrelated task can progress during storage waits. Exercise cancellation before/after commit, queue saturation, ordered batches, EOF/error fusion and bounded memory. Retain measured benchmarks separately from correctness assertions.

### A06 — P1: make aggregate transitions safe across an application panic

- [x] **Fixed.** State is an `Option` holding the owned application state; a fold takes it out and installs the complete result only after all events succeed. Unwinding leaves no accessible replacement or partial state. `state()` returns typed `PoisonedAggregate`; decisions/reactions distinguish kernel integrity from application rejection via `DecisionError`. Replay and commit reject poisoned roots, and repository save checks integrity before encoding or appending. Version remains diagnostic metadata: replay retains the prior completed boundary; a post-persist fold retains the caller's acknowledged boundary. Recovery requires a new root loaded from committed history; no database rollback is implied. Updated root/CQRS callers and retained panic tests, activated the original restored-123 regression as `panicking_replay_cannot_expose_usable_inconsistent_root`, and added [panic_safety.rs](crates/store/tests/panic_safety.rs). Non-Clone state tests inject first/middle/last panics in replay and committed folds; save/execute/saga ports reject reuse without new rows or intents. Recovered history has exactly versions 1–4, state 4, and a subsequent save reaches version/state 5. Verified full kernel tests (214 passed), full store tests (603 passed), macro and signed/Fjall example suites (67 passed), the final panic/CQRS/lifecycle tests, non-Postgres all-feature/all-target workspace Clippy and the derive smoke crate on `thumbv7em-none-eabihf`. Commit range derivation/prevalidation is recorded in A07.

**Code:** [aggregate.rs](crates/mnesis/src/aggregate.rs) `replay`, `commit_persisted`, `apply_events`; [repository.rs](crates/store/src/repository.rs) post-append fold.

**Fix:** ensure no usable root can escape with state/version describing different histories. Choose an explicit design: consuming transitions, a poisoned/uninitialized state that rejects all further use, or transactional staging with a suitable state-copy strategy. The current unconstrained owned `apply` cannot recover its consumed old state after a panic without such a design change. Correct the unconditional atomicity claims. If the append already committed, recovery must reload; do not report or imply that the database rolled back.

**Accept:** deterministic first/middle/last-event panics in replay and committed multi-event folds; `catch_unwind` cannot expose a reusable inconsistent root. Check persistence is exactly once and recovery loads the committed history. Adapt the retained assertion if the selected API makes reuse impossible instead of restoring old state.

### A08 — P1: count replay work rather than absolute version

- [x] **Fixed.** Each new/restored root starts a private successful-replay counter at zero. Contiguous version checks remain independent; a successful fold advances the counter with checked arithmetic. Validation failures and command commits consume no replay work. The budget is per root instance: snapshots represent previous work, and loading/restoring starts a new session. Activated the high-version snapshot repro and added [replay_budget.rs](crates/store/tests/replay_budget.rs): a two-event budget at fresh/high snapshot boundaries, limit/limit+1 behavior, gap/duplicate rejection without lost capacity, commits without replay cost, a one-event tail reaching `u64::MAX`, and a genuine snapshot repository whose two-event tail loads while a third event returns a typed limit error. Full kernel/store suites pass (825 tests, 0 failures), final four-case replay-budget tests pass, non-Postgres workspace all-feature/all-target Clippy passes, and the bare-metal derive smoke check passes.

**Code:** [aggregate.rs](crates/mnesis/src/aggregate.rs) `replay` compares the incoming version to `MAX_REHYDRATION_EVENTS`.

**Fix:** count successfully replayed events in the current rehydration operation, starting at zero for both fresh construction and snapshot restoration. Preserve contiguous version checks independently. Clarify when a replay session starts/ends; command commits must not consume this replay budget.

**Accept:** a small custom limit exercises limit−1, limit and limit+1 from fresh and high-version restored roots; rejected/out-of-order events do not consume budget or alter state. A short tail remains loadable at any valid stream version.

### A09 — P2: restore a maximum-version snapshot without requiring a successor

- [x] **Fixed.** Snapshot hits retain the restored root plus an optional tail start. A hit at `u64::MAX` returns the root directly; ordinary hits replay from their checked successor. Cache misses, stale schemas and hydrate errors retain the existing fallback behavior. Activated `ceiling_snapshot_is_restored_without_replay` and added a three-case integration check for valid ceiling, valid near-ceiling and stale-schema ceiling snapshots. An ordinary fallback row distinguishes preserved snapshot state from replayed state; no maximum-length history is fabricated. A subsequent ceiling save returns typed overflow and preserves state/version.
